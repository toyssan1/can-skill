# SAE J1939 and relatives (NMEA 2000, ISOBUS, FMS)

J1939 is the CAN protocol of trucks, buses, construction and agricultural machinery, generators and marine engines. Unlike passenger-car CAN it is standardised: the same message means the same thing across manufacturers, so most of a truck's bus can be decoded without reverse engineering.

## Identifier layout and PGN

Always 29-bit IDs, 250 kbit/s (J1939-11/-15) or 500 kbit/s (J1939-14, newer vehicles).

```
bits 28-26  priority (0 highest; 3 typical for control, 6 for information, 7 lowest)
bit  25     extended data page (0)
bit  24     data page
bits 23-16  PDU format (PF)
bits 15-8   PDU specific (PS)
bits 7-0    source address (SA)
```

- **PDU1** (PF < 240): PS is a **destination address**. The PGN is `EDP, DP, PF, 00`: the two page bits are part of it. Used for requests, commands, transport.
- **PDU2** (PF >= 240): PS is a group extension and part of the PGN. Always broadcast.

```python
def j1939(can_id):
    pf, ps = (can_id >> 16) & 0xFF, (can_id >> 8) & 0xFF
    dp = (can_id >> 24) & 0x03
    pgn = (dp << 16) | (pf << 8) | (ps if pf >= 240 else 0)
    return dict(priority=(can_id >> 26) & 7, pgn=pgn, da=ps if pf < 240 else None, sa=can_id & 0xFF)
```

| CAN ID | Priority | PGN | Source |
|---|---|---|---|
| `0CF00400` | 3 | 61444 (0xF004) EEC1 | 0 engine |
| `18FEEE00` | 6 | 65262 (0xFEEE) ET1 | 0 engine |
| `18FEF100` | 6 | 65265 (0xFEF1) CCVS | 0 engine |
| `18EAFFF9` | 6 | 59904 (0xEA00) request, to all | 249 service tool |
| `18ECFF00` | 6 | 60416 (0xEC00) TP.CM, to all (BAM) | 0 engine |

Filter on the PGN, not the whole ID: the same PGN arrives from different source addresses and, in principle, with different priorities. Mask `0x03FFFF00` for PDU2, `0x03FF0000` for PDU1: bits 25 and 24 (extended data page and data page) belong to the PGN, which is how `j1939_fields()` in `scripts/can_log_analyze.py` extracts it. In a SocketCAN filter also set the extended-frame flag in the mask (`0x80000000`) so that only 29-bit frames match.

## Data conventions

- Multi-byte values are **little-endian** (least significant byte first). SAE documents number bytes from 1 and bits from 1; byte 1 is `data[0]`.
- Most parameter groups are sent as 8 bytes with unused bytes `0xFF`. Some frames are shorter (a Request, PGN 59904, carries 3), and anything longer than 8 bytes goes through the transport protocol.
- Reserved ranges mark validity. 1 byte: `0x00`-`0xFA` valid, `0xFE` error, `0xFF` not available. 2 bytes: up to `0xFAFF` valid, `0xFExx` error, `0xFFxx` not available. Check these before scaling; a coolant reading of 215 degC is `0xFF`, not a hot engine.
- 2-bit status fields: `00` off, `01` on, `10` error, `11` not available.
- Each signal is an SPN (suspect parameter number) with a fixed resolution and offset.

## Common PGNs and SPNs

Byte numbers are 1-based as in the standard.

| PGN | Name | Rate | Signals (byte: SPN name, scaling) |
|---|---|---|---|
| 61444 (F004) | EEC1 | 10-20 ms | 2: driver demand torque, 1 %/bit, -125. 3: actual engine torque, 1 %/bit, -125. **4-5: engine speed (SPN 190), 0.125 rpm/bit** |
| 61443 (F003) | EEC2 | 50 ms | 2: accelerator pedal position (SPN 91), 0.4 %/bit. 3: engine load at current speed (SPN 92), 1 %/bit |
| 61445 (F005) | ETC2 | 100 ms | 1: selected gear, -125. 4: current gear (SPN 523), -125 (251 = park) |
| 65262 (FEEE) | ET1 | 1 s | **1: coolant temperature (SPN 110), 1 degC/bit, -40.** 2: fuel temperature, -40. 3-4: oil temperature (SPN 175), 0.03125 degC/bit, -273 |
| 65263 (FEEF) | EFL/P1 | 0.5 s | 1: fuel delivery pressure, 4 kPa/bit. 3: oil level, 0.4 %/bit. **4: oil pressure (SPN 100), 4 kPa/bit.** 8: coolant level, 0.4 %/bit |
| 65265 (FEF1) | CCVS1 | 100 ms | **2-3: wheel-based vehicle speed (SPN 84), 1/256 km/h per bit.** 4: brake switch (bits 5-6), clutch switch (bits 7-8) |
| 65266 (FEF2) | LFE1 | 100 ms | 1-2: fuel rate (SPN 183), 0.05 L/h per bit. 3-4: instantaneous fuel economy, 1/512 km/L per bit. 7: throttle position, 0.4 %/bit |
| 65269 (FEF5) | AMB | 1 s | 1: barometric pressure, 0.5 kPa/bit. 4-5: ambient air temperature (SPN 171), 0.03125 degC/bit, -273 |
| 65270 (FEF6) | IC1 | 0.5 s | 2: intake manifold (boost) pressure (SPN 102), 2 kPa/bit. 3: intake manifold temperature, -40. 6-7: exhaust gas temperature, 0.03125 degC/bit, -273 |
| 65271 (FEF7) | VEP1 | 1 s | **5-6: battery potential (SPN 168), 0.05 V/bit.** 3-4: charging system potential, 0.05 V/bit |
| 65276 (FEFC) | DD | 1 s | 2: fuel level (SPN 96), 0.4 %/bit |
| 65253 (FEE5) | HOURS | on request | 1-4: total engine hours (SPN 247), 0.05 h/bit |
| 65248 (FEE0) | VD | on request / 1 s | 5-8: total vehicle distance (SPN 245), 0.125 km/bit |
| 65217 (FEC1) | VDHR | 1 s | 1-4: high-resolution total distance (SPN 917), 5 m/bit |
| 65257 (FEE9) | LFC | on request | 5-8: total fuel used (SPN 250), 0.5 L/bit |
| 65260 (FEEC) | VI | on request | VIN in ASCII, terminated by `*` (multi-packet) |
| 65226 (FECA) | DM1 | 1 s while faults active | active trouble codes, see below |

Worked example, `0CF00400#F07D84681300F084`: bytes 4-5 are `68 13`, little-endian 0x1368 = 4968, x 0.125 = 621 rpm. Byte 3 `0x84` = 132 - 125 = 7 % torque.

The full SPN and PGN definitions are in the SAE J1939 Digital Annex (J1939DA), which is a paid, copyrighted spreadsheet. Public decodings exist for the common parameters; for anything not in the table above, say that the authoritative scaling is in J1939DA or a licensed J1939 DBC instead of guessing. Proprietary messages use PGN 61184 (0xEF00, proprietary A) and 65280-65535 (0xFF00-0xFFFF, proprietary B): those do need reverse engineering.

## Requesting data

Many PGNs are only sent on request. Send PGN 59904 (0xEA00) with the wanted PGN in 3 bytes, little-endian, DLC 3:

```
18EAFFF9#E5FE00        ask everyone for PGN 65253 (0xFEE5) engine hours
18EA00F9#ECFE00        ask the engine (address 0) for PGN 65260 VIN
```

A node that cannot comply answers a destination-specific request with a NACK: PGN 59392 (0xE800), byte 1 = 1, bytes 6-8 = the PGN. Global requests are silently ignored by nodes that do not support the PGN.

## Addresses and address claiming

Common preferred addresses: 0 engine, 3 transmission, 11 brakes (ABS/EBS), 15 engine retarder, 16 driveline retarder, 23 instrument cluster, 33 body controller, 49 cab controller, 61 exhaust aftertreatment, 249 and 250 off-board service tools, 254 null (no address), 255 global.

On start-up a node sends Address Claimed, PGN 60928 (0xEE00), to 255 with its 64-bit NAME as data. If two nodes claim one address, the lower NAME value wins and the loser claims another address or goes silent (sending "cannot claim" from address 254). A device that transmits on a J1939 network should claim an address: use 249 for a diagnostic tool, or a free address with a properly formed NAME. A passive logger does not need one.

## Transport protocol (messages over 8 bytes)

Up to 1785 bytes (255 packets x 7). Two modes, both using TP.CM PGN 60416 (0xEC00) for control and TP.DT PGN 60160 (0xEB00) for data.

**BAM (broadcast, to 255)**: no handshake, 50-200 ms between packets.
```
18ECFF00#20 0E 00 02 FF CA FE 00     BAM: 0x000E = 14 bytes, 2 packets, PGN 0xFECA (DM1)
18EBFF00#01 xx xx xx xx xx xx xx     packet 1: sequence number, then 7 data bytes
18EBFF00#02 xx xx xx xx xx xx xx     packet 2 (unused bytes FF)
```

**RTS/CTS (to one destination)**:

| Control byte | Message | Layout after the control byte |
|---|---|---|
| 0x10 | RTS | size (2, LE), total packets, max packets per CTS, PGN (3, LE) |
| 0x11 | CTS | packets you may send now, next packet number, FF FF, PGN |
| 0x13 | EndOfMsgAck | size (2), total packets, FF, PGN |
| 0x20 | BAM | size (2), total packets, FF, PGN |
| 0xFF | Abort | reason, FF FF FF, PGN |

Reassemble per (source, destination) pair. A capture that begins mid-transfer cannot be decoded for that message.

## Diagnostics: DM1 and friends

**DM1 (PGN 65226)**: active trouble codes, broadcast every second while any fault is active.

- Bytes 1-2: lamp status. Byte 1 bit pairs, from the top: malfunction indicator, red stop, amber warning, protect (`01` = on). Byte 2: flash states.
- Then 4 bytes per trouble code:
  ```
  byte 1: SPN bits 7-0
  byte 2: SPN bits 15-8
  byte 3: bits 7-5 = SPN bits 18-16, bits 4-0 = FMI
  byte 4: bit 7 = conversion method, bits 6-0 = occurrence count
  ```
- One code fits in a single frame. Two or more make the message longer than 8 bytes, so it arrives by BAM.
- No active faults: `00 FF 00 00 00 00 FF FF` (lamps off, SPN 0, FMI 0).

Example: `18FECA00#04FF6E000301FFFF` (`04 FF 6E 00 03 01 FF FF`): amber warning lamp on; SPN = 0x00006E = 110 (coolant temperature), FMI 3, count 1: coolant temperature sensor voltage high.

| FMI | Meaning | FMI | Meaning |
|---|---|---|---|
| 0 | data valid, above normal, most severe | 9 | abnormal update rate (message missing) |
| 1 | data valid, below normal, most severe | 10 | abnormal rate of change |
| 2 | data erratic, intermittent or incorrect | 11 | root cause not known |
| 3 | voltage above normal or shorted high | 12 | bad intelligent device or component |
| 4 | voltage below normal or shorted low | 13 | out of calibration |
| 5 | current below normal or open circuit | 14 | special instructions |
| 6 | current above normal or grounded | 15 / 16 | above normal, least / moderately severe |
| 7 | mechanical system not responding | 17 / 18 | below normal, least / moderately severe |
| 8 | abnormal frequency, pulse width or period | 19 | received network data in error |
| | | 31 | condition exists |

Other diagnostic messages: DM2 (65227) previously active codes, DM3 (65228) clear previously active, DM11 (65235) clear active, DM4 (65229) freeze frame, DM5 (65230) readiness, DM12 (65236) emissions-related active codes. All are obtained with a request. DM3 and DM11 erase fault memory: treat them like OBD service 04.

Connector: 9-pin Deutsch, C = CAN high, D = CAN low, A = ground, B = battery. Black is 250 kbit/s, green is 500 kbit/s (see `physical-layer.md`). Heavy vehicles are 12 V or 24 V: check before powering anything from pin B.

## Tooling

- Linux has a J1939 socket family (`can-j1939`, kernel 5.4+) that handles address claiming and transport. can-utils: `j1939spy`, `j1939cat`, `j1939sr`, `j1939acd`, `testj1939`.
- `candump can0,0CF00400:1FFFFFFF` or by PGN from any source: `candump can0,00F00400:83FFFF00` (PGN bits plus the extended-frame flag).
- Python: the `can-j1939` and `python-j1939` packages on top of python-can; `cantools` decodes J1939 DBC files and splits a frame ID into priority, PGN and source address, but it decodes the payload you hand it: reassemble transport-protocol messages first, with the kernel J1939 socket or `can-j1939`.
- A J1939 DBC (licensed from SAE via vendors such as CSS Electronics, or the vehicle maker's own) loads into SavvyCAN, cantools, Vector and PEAK tools and decodes most of a truck's traffic directly.
- Wireshark dissects J1939 including transport protocol.

## NMEA 2000

Marine instrument network built on J1939 conventions: 29-bit IDs with the same priority/PGN/source layout, 250 kbit/s, mandatory address claiming, powered backbone with Micro-C (M12) connectors.

- Single-frame PGNs work like J1939.
- **Fast packet** replaces J1939 transport for messages up to 223 bytes. First frame: byte 0 = sequence counter (bits 7-5) and frame counter 0 (bits 4-0), byte 1 = total length, then 6 data bytes. Following frames: byte 0 = sequence and frame counter, then 7 data bytes. No handshake. Whether a PGN is single-frame or fast-packet is defined per PGN, not signalled on the wire, so a decoder needs the database.
- Common PGNs: 127488 engine parameters rapid (rpm, 0.25 rpm/bit), 127489 engine parameters dynamic (oil pressure, temperatures, hours), 127505 fluid level, 127508 battery status, 128259 speed through water, 128267 water depth, 129025 position rapid, 129026 course and speed over ground, 129029 GNSS position, 130306 wind, 130312 temperature.
- The standard is paid and under NDA. The open **canboat** project maintains a reverse-engineered PGN database (`pgns.json`) and an `analyzer` tool that decodes candump logs; Signal K builds on it.

## ISOBUS, FMS, RV-C, J1939-22

- **ISOBUS (ISO 11783)**: agricultural J1939 with virtual terminals, task controllers and implement control; adds the extended transport protocol (ETP) for transfers up to 117 MB.
- **FMS-Standard**: the European truck makers' agreed read-only gateway exposing a fixed subset of J1939 PGNs (speed, fuel, distance, tachograph) for fleet telematics. If a truck has an FMS connector, use it: it is designed for third-party access.
- **RV-C**: recreational-vehicle protocol with J1939-style IDs at 250 kbit/s and a public specification.
- **J1939-22**: J1939 on CAN FD, with several parameter groups packed into one frame.
